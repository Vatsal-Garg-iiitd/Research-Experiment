# Experimental methodology

## Research question and estimand

Estimate, within each fixed model/task/protocol, how evaluation performance changes with additional native computational budget and measured wall time. The primary quantities are adjacent-budget performance change and change per additional training second. These are descriptive within-run quantities; they are not causal population estimates without repeated seeds and controlled runs.

## Evidence classes

1. **Local measurement:** value generated by a saved local run with configuration, status, budget, and hardware recorded.
2. **Published:** value copied from a cited paper/report; never presented as locally reproduced.
3. **Derived:** deterministic calculation from reported or measured inputs (e.g., perplexity = exp(cross-entropy)); formula and inputs must be retained.
4. **Unavailable:** blank, not zero, when no reliable value exists.

## Existing experiment protocol

> **Protocol update (2026-11-07):** The following historic pilot description is retained for provenance. Expanded runs use several distinct scopes: 10K train / 2K validation Fashion-MNIST runs, MLP/LeNet data-size runs, RL environment-interaction schedules, and LLM checkpoint evaluations. Seeds, budgets, splits, platform, and deviations are recorded per run. The completion matrix and execution log are authoritative for current status.

- Conventional pilots use Fashion-MNIST subsets, seed 11, and native units appropriate to the algorithm; training is on DirectML for neural pilots, CPU for scikit-learn and RL.
- New full-suite vision pilots use 2,500 total images (2,000 train, 500 held-out), a single seed, and generally a single optimization pass. They are labeled pilots. The held-out values are not final independent test estimates.
- Semi-supervised pilots use a fixed 10% labeled subset, short warm start and one SSL pass. The code uses compact feasibility recipes and is not a faithful full benchmark reproduction for FixMatch/MixMatch.
- RL pilots use a single seed and 5,000 environment steps, with five evaluation episodes. DQN uses CartPole, SAC Pendulum. This is not adequate for stable RL comparison.
- LLM local evaluation uses CPU fp32 on a short prefix, one sequence, no downstream benchmark. `main` revisions must not be counted as additional checkpoints when identical to named step revisions.
- Literature data remain a separate evidence class; paper-specific metrics and compute units are not pooled with local task outcomes.

## Analysis conventions

For higher-is-better metrics, improvement is `score_next - score_previous`; for lower-is-better metrics, improvement is `score_previous - score_next`. Budget marginal gain is divided by native budget increment. Time efficiency is improvement divided by positive incremental cumulative training time from the same seed/configuration. Never aggregate incomparable units or metrics. Saturation is not inferred from one increment or a single seed. Means, standard deviations and confidence intervals are only calculated across genuinely independent, aligned repetitions.

## Required confirmatory protocol (not yet completed)

Use fixed train/validation/test partitions, train-only preprocessing, validation-based model selection, and one final test evaluation. Target at least three conventional seeds (five for RL where feasible), multi-point native budgets, saved per-epoch/step histories, model/config identity, environment/package versions, and incremental checkpoints. Neural budgets target 1/3/5/10/20/30 epochs; RF tree counts; unsupervised algorithm-specific iterations/initializations/parameters; SSL multiple label fractions and supervised labeled-only baseline; RL environment steps. LLM comparisons require a fixed full dataset/token budget, standardized harness tasks and distinct training-token/checkpoint progress. Exact protocols must be locked in a run config before confirmatory execution.

## Limitations

The current pilots do not satisfy the confirmatory protocol. In particular, small subsets, test/held-out reuse, single seeds, short LLM prefixes, incomplete architecture fidelity, and missing per-epoch logs limit conclusions. Do not describe the study as complete until those gaps are addressed or explicitly impossible for each target.

## 2026-11-07 study extensions

- Mean Teacher/FixMatch/MixMatch use same fixed 10k/2k Fashion-MNIST development split, seeds 11/23/37, labeled fractions 1/5/10/20/40%, 3 epochs and independent official test endpoints. MLP 784-256-10; EMA=.99, FixMatch confidence=.95, MixMatch temperature=.5 and MixUp alpha=.75. Photometric perturbations are a task adaptation; MixMatch runs CPU because DirectML indexing failed.
- Actual sklearn LabelPropagation was investigated separately from legacy LabelSpreading. The graph is a symmetric-union 10-neighbor graph over PCA-32 transductive features (test labels withheld); maximum iterations swept through 2000 at tolerance 1e-3. The graph was connected with no isolated nodes; convergence reached at 197/374/438 iterations across seeds.
- DBSCAN data-size scaling fixes eps=2.88036, min_samples=5 and PCA-32 feature representation; nested samples 2.5K/5K/10K and three seeds. This is size-cost scaling, distinct from hyperparameter sensitivity.
